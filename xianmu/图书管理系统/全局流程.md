1.项目描述
1.1 项目介绍
基于C语言和数据结构（链表），构筑一个基于命令行的图书管理系统。该系统能够实现图书信息的增删改查、借还管理、用户管理等功能，为图书馆或书店提供图书管理解决方案。

1.2
支持管理员登录（管理员不需要注册，可以程序内置固定账号密码）
支持普通用户注册与登录

支持图书模糊搜索（如输入部分书名、作者、出版社等即可查询）
支持普通图书借还管理功能
支持图书的库存管理

1.3

支持图书统计报表功能

    四、细节处理
        1.重复 ID 检查：加用户/加图书时 ID 不能重复；删除/查询统一按 ID 操作（书名会重名）。
        2.同种书限借 1 本：现实中每用户每种书限借 1 本，借书前查重。
        3.数据持久化方案（选做）：建议 data/ 下三个文本文件，每行一条用 | 分隔：
            users.txt：ID|用户名|密码
            books.txt：ID|书名|作者|出版社|库存|借出数
            records.txt：用户ID|图书ID|借书时间|还书时间
            启动时加载、退出时保存（或每次操作后保存）。比二进制好调试。
        4.书名可能带空格：scanf("%s") 遇到空格会截断，建议用 fgets 或 scanf("%[^\n]") 读字符串。
        5.退出时释放所有链表内存（free 所有节点），避免内存泄漏。
        6.借书前判断 stock > 0，为 0 提示"库存不足"——这就是"库存管理"的自动实现了，管理员无需手动改库存，添加图书时设好初始值即可。
        7.还书时除了 stock+1，还要在对应 BorrowRecord 里填 return_time（标记"已还"），这样查询借阅记录能区分"借阅中"和"历史记录"。
        8.删除图书时，如果它有"未还"的借阅记录，数据会不一致（记录还在但书没了）。简单处理：删除前查一下该书有没有未还记录，有就提示"有人借着，不能删"。
        9.其他：根据需求添加其他功能，如图书统计报表、用户管理等。

    六、问题
    1、
        原因:我注意到了我写代码编译测试时，while循环太快根本看不清提示信息，我的想法加个sleep(1)和输入回车在进行下面的操作，但是AI有另一个想法,于是有了下面的过程:

        坑：scanf 残留的换行符会被 getchar 直接吃掉
        您的代码里大量用 scanf("%d", ...) 或 scanf("%s", ...)——scanf 读完数字/字符串后，缓冲区里还留着用户敲的 \n。这时如果直接 getchar()，它立刻读到那个残留换行，根本不会等用户按键，瞬间继续。
        所以正确顺序是：先清残留 → 提示 → 再等按键。

        EOF 后 scanf 永远失败，而菜单的 while(1) 里失败就 continue 重新循环——没有出口。
        在 scanf 失败分支里先检测 EOF，是 EOF 就直接退出当前菜单：

        解决方法:
        // 暂停，等待用户按 Enter 继续
        void pause_enter(void){
            int c;
            while((c = getchar()) != '\n' && c != EOF);  // 1. 清掉 scanf 残留的换行
            printf("按 Enter 键继续...\n");
            while(getchar() != '\n');                     // 2. 真正等用户按键
        }
        这样 EOF 时菜单会干净地返回上一层，不会无限刷屏。

        原因：这是我的想法，创建时也应该找到最后的id+1，例如：
        //删除前，要把这个book的后面的书籍book_id+1
                Book *next = p->list->next;
                if(next != NULL){
                    next->book_id--;
                    next = next->list->next;
                }
        AI的说法：更重要的是设计上就不该重排 ID：图书 ID 就像学号——删掉 5 号学生，不会把 6 号改成 5 号。而且借阅记录（BorrowRecord）里存的是 book_id，删除书后如果重排 ID，所有借阅记录都会指向错误的书！ID 不连续完全没问题，直接删，什么都不用改
        核心原因：借阅记录里存着 book_id
        您的 BorrowRecord 结构体里存的是 book_id（谁借了哪本书）。假设：
        用户A 借了 3 号书（未还）→ 记录：userA, 3, 借出中
        管理员删掉了 3 号书（其实不该让删，但有这个场景）
        管理员又添加新书 → ID 复用成 3
        → 新书 3 号"继承"了 userA 的借阅记录！
        → 用户A 的"借阅中"记录指向了一本完全不相干的新书
        数据就乱了。ID 一旦复用，历史记录全部张冠李戴。所以主键（ID）必须永久唯一。

        现实世界的例子，全是"不复用"
        身份证号：人注销了，号码不会给新人
        学号：退学的学号不会发给新生
        订单号：取消的订单号不会给新订单
        数据库自增主键（MySQL 的 AUTO_INCREMENT）：删了行，主键不会回退复用
        这是所有正经系统的通用规则，不是省事，是数据一致性的要求。

        ！！！最终："删除图书后 ID 不复用，采用最大 ID+1 分配新 ID。因为借阅记录通过 book_id 关联图书，复用 ID 会导致新书继承旧书的借阅历史，破坏数据一致性。这也是数据库主键设计的通用原则。"


    七、图书管理系统 · 易忘细节清单
                一、编译 & 头文件
                编译命令：gcc src/*.c -Iinclude -o main——别加 -std=c99，kernel_list.h 用了 GNU 扩展（typeof、({ })）
                头文件自包含：每个 .h 用到 struct list_head 就自己 #include "kernel_list.h"，别依赖使用方的包含顺序
                extern 放 typedef 后面：extern User admin; 必须在 }User; 之后，否则编译器不认识 User（这坑踩过一次，连环报错）
                警惕循环包含：user.h 和 borrow.h 互相 include = 循环，删掉不需要的那边
                二、结构体（最常踩的坑）
                写代码前先对照 .h 字段名：book_id 不是 id、inventory 不是 stock、book_name 不是 name、user_id 不是 user_name——字段名错了编译直接挂
                函数签名一致：声明和定义必须一模一样（返回类型、参数个数），void login_user() 和 bool login_user(char*, char*) 不能混
                变量别和函数重名：bool is_number = is_number(borrow); 直接冲突
                三、内核链表
                节点必须 malloc：栈上变量挂链表 = 悬空指针，函数返回就崩（Book *p = malloc(sizeof(Book))）
                删除两步走：list_del_init(&p->list); 然后 free(p);——顺序不能反
                删多个节点用 list_for_each_entry_safe：普通遍历中删当前节点会断链
                链表头初始化：LIST_HEAD(user_list) 声明即初始化，或 INIT_LIST_HEAD(&user_list)
                四、输入输出（scanf 家族）
                scanf 残留换行：读数字后缓冲区留 \n，直接 getchar() 会吞掉它——先 while((c = getchar()) != '\n' && c != EOF);
                EOF 死循环：所有 while(getchar() != '\n') 必须加 && c != EOF，否则输入结束就死循环
                数组别加 &：sscanf(line, "%s", p->name) 不是 &p->name
                字符串带空格会截断：scanf("%s") 遇空格停，书名"Unix环境高级编程"没空格才侥幸
                pause_enter 会吞管道输入：交互模式正常，但 ./main < 文件 重定向时 getchar 会吃掉后续输入
                五、业务逻辑
                ID 不复用：新 ID = 最大 ID + 1（不是节点数+1）；ID 是身份不是序号，删了不重排
                "一个框两种匹配"：先 is_all_digit() 判断是不是数字，再决定按 ID 还是按名字——别用 atoi 判断（"abc"→0 误判）
                借书三查：书存在？库存 > 0？才能借
                还书三条件：user_id 匹配（只能还自己的）+ book_id 匹配 + return_time[0]=='\0'（防止重复还）——三个条件缺一不可
                当前用户：登录成功就 current_user = user;，借还全靠它
                malloc 必 free：提前 return 的每个分支都要释放（未找到、库存不足时）
                模糊查询不 break：遍历完整条链表，把所有匹配的都打出来
                六、持久化
                读写必须对称：write 写的格式 = load 读的格式（表头、分隔符、字段顺序全部一致）
                表头要么都写要么都不写：write 写表头，load 跳表头；两边必须配套
                ctime 自带换行：ctime() 结果末尾有 \n，写文件前用 strcspn(bt, "\n") 去掉，否则记录断行
                load 在 init 后调用，write 在退出前调用：main 里 init() → load_data() → main_menu() → write_data()
